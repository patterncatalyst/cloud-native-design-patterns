# Example 02: Communications, C++

Two services, built from this directory (the compose build context):

| Service | Port | Stack |
|---------|------|-------|
| `order-service` | 8080 | Drogon (REST), cppgraphqlgen (GraphQL), grpc++ client, librdkafka C++ (`rdkafka++`) producer, libpq |
| `inventory-service` | 50051 | grpc++ sync server |

Toolchain: C++23 (`CMAKE_CXX_STANDARD 23`, no extensions), GCC 15 (`gcc-toolset-15`), CMake 4.4.4,
Ninja 1.13.2, Conan 2.33.0, on `ubi10/ubi:10.2`; runtime `ubi10/ubi-minimal:10.2` as UID 1001 (group 0)
with libstdc++ and libgcc linked statically.

## order-service

- **Kafka**: `kafka_publisher.hpp` produces `order.placed` with the librdkafka C++ API
  (`acks=all`, idempotent producer, asynchronous `produce()`, a poll thread serving the delivery-report
  callback, `flush()` on shutdown). modern-cpp-kafka is archived upstream.
- **GraphQL**: cppgraphqlgen 4.5.9. `src/graphql/schema.graphql` is the schema; the C++ next to it
  (`OrdersSchema.*`, `OrderObject.*`, `QueryObject.*`) is **generated by schemagen and committed**. The
  resolvers are in `src/graphql_api.hpp`; a field is only read from the repository when the query selects
  it. Queries: `orders(limit: Int = 10)` and `order(id: String!)`. JSON goes through jsoncpp
  (`src/json_bridge.hpp`), so RapidJSON is not needed.
- **Postgres**: libpq directly (`src/pg_orders.hpp`), every statement parameterised with `PQexecParams`.
- **Tests**: `tests/graphql_test.cpp` runs under `ctest` inside the image build (fake repository, no network).

cppgraphqlgen is not on ConanCenter, so its recipe lives in `order-service/conan-recipes/cppgraphqlgen/`
and the Containerfile runs `conan export` on it before `conan install`.

### Regenerating the GraphQL code

After changing `schema.graphql` (from this `cpp/` directory):

```bash
docker build --target schemagen -t cndp-02-schemagen -f order-service/Containerfile .
(cd order-service/src/graphql && \
 docker run --rm -v "$PWD:/work:Z" --user "$(id -u):$(id -g)" cndp-02-schemagen \
   --schema=schema.graphql --prefix=Orders --namespace=orders)
```

The `schemagen` stage builds the pinned schemagen 4.5.9 (the recipe's `schemagen=True` option, which pulls
Boost.program_options); the normal image build never runs it. Generated headers check the library version
(`static_assert`), so a mismatch fails the build rather than misbehaving.
